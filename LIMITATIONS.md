# Limitations

- A matching SHA-256 digest proves byte equality with the requester's commitment, not source authenticity, truth, or independence.
- A validator repeats HTTP retrieval and LLM classification. Identical evidence or classification is not guaranteed; consensus may remain undetermined and no decision will be recorded.
- HTTPS URLs must use ASCII DNS-style hostnames with distinct canonical hostnames; localhost, local-only suffixes, IP literals, userinfo, non-default ports, fragments, controls, backslashes, reserved percent escapes, repeated separators, and dot-segment paths are rejected. This is syntax validation only. It does not establish that a hostname is publicly routable, enforce publisher allowlists or registrable-domain ownership diversity, resolve/pin DNS, check resolved IPs, validate redirected destinations, attest TLS peers, or verify publisher signatures. DNS rebinding, DNS answers that point to private IPs, and redirect-to-private destinations are not ruled out by the contract. GenVM runtime egress behavior was not verified in a real Studio environment.
- The exact response body can vary due to redirects, dynamic pages, compression/encoding, caching, or infrastructure. Prefer immutable archival endpoints and precompute the digest of the exact response bytes.
- The contract currently accepts UTF-8 bodies up to 6,000 bytes per URL entry and 2–5 distinct canonical hostnames. Hostnames, including sibling subdomains, can share ownership or content. These counters are URL-entry observations only and do not establish independent publishers; a trustworthy publisher registry or authenticated publisher signatures would be required for that guarantee.
- `policy_sha256` now hashes canonical JSON with the versioned domain `ConsensusGuard.Policy.v1` and separately named claim and criteria fields. This removes the previous newline-delimiter ambiguity. Historical hashes are not rewritten; no deployed records exist in this workspace.
- When transport/DNS exceptions, HTTP 408/425/429, or 5xx responses leave fewer than the configured threshold, the contract classifies the fetch as retryable `UNAVAILABLE`, skips the LLM, and reverts; this is a policy classification, not proof the failure is temporary. Other returned non-2xx statuses become `HTTP_ERROR` for that attempt and can produce an agreed `INCONCLUSIVE` with one appeal. Some such status codes can themselves be temporary; the contract does not infer permanence. A persistently unavailable required host can block progress.
- The support/refutation threshold is a configured quorum, not a majority requirement. With `m = 2`, two `SUPPORTS` and three `UNCLEAR` among five verified URLs produces `VERIFIED`; callers must read the counts and reason code and must not interpret the label as majority agreement or objective truth.
- A one-time appeal is submitted by the requester. It is not an independent external appeal tribunal and does not replace protocol-level GenLayer appeals.
- Studio Dev deployment and transaction evidence exists and is documented. Public testnet deployment has not been run; Studio Dev is not a public testnet. Explorer reports an approximate 0.000097 GEN fee for the resolve transaction. No Portal review/submission has occurred.
